# پول | اپلیکیشن مدیریت مالی

نسخه اولیه فرانت‌اند با HTML5، Tailwind CSS v4، Vanilla JavaScript، Vite و IndexedDB.

## مستندات
راهنمای کامل مراحل توسعه، ساختار پروژه، مدل داده و مسیر مهاجرت به Laravel در فایل [راهنمای توسعه](docs/DEVELOPMENT-GUIDE.md) قرار دارد.

## پیش‌نیازها
- Node.js نسخه LTS
- npm

## نصب و اجرا
```bash
git clone https://github.com/MohsenFakori/pool.git
cd pool
npm install
npm run dev
```

ساخت و پیش‌نمایش نسخه production:
```bash
npm run build
npm run preview
```

## اصول معماری و کدنویسی
- تمام استایل‌های رابط کاربری با utility classهای Tailwind نوشته می‌شوند.
- فایل `src/styles/main.css` فقط ورودی Tailwind، import فونت و آیکن، و design tokenها در `@theme` را دارد؛ هیچ selector یا قانون CSS سفارشی برای اجزای رابط تعریف نمی‌شود.
- در صفحات از inline style استفاده نمی‌شود.
- داده‌های نمایشی در `src/data/demo-data.js` متمرکز هستند؛ این داده‌ها fixture آزمایشی‌اند و نباید با منطق برنامه مخلوط شوند.
- تنظیمات، مقادیر ثابت محصول، منوها و رمز پیش‌فرض در `src/app/config.js` قرار دارند.
- منطق احراز هویت در Service و دسترسی داده در Repositoryها متمرکز است.
- اندازه قاب برنامه موبایلی و ثابت است و breakpoint واکنش‌گرا تعریف نشده است.

## جریان شروع و ورود
1. در اولین اجرا، صفحه خوش‌آمد نمایش داده می‌شود.
2. با انتخاب شروع، وضعیت نمایش خوش‌آمد در LocalStorage ثبت و صفحه ورود باز می‌شود.
3. کاربر ثبت‌نام‌نشده می‌تواند از صفحه ورود به ثبت‌نام برود و فقط نام کاربری انتخاب کند.
4. رمز پیش‌فرض از تنظیم مرکزی خوانده می‌شود و در نسخه نمایشی مقدار `123456` دارد.
5. حساب و پروفایل در IndexedDB ذخیره می‌شوند.
6. پس از ورود، رکورد نشست در IndexedDB و شناسه نشست فعال در LocalStorage ثبت می‌شود.
7. در اجرای بعدی، نشست بررسی و در صورت معتبر بودن، داشبورد همان کاربر باز می‌شود.
8. خروج، رکورد نشست جاری و شناسه آن را حذف می‌کند؛ حساب کاربر باقی می‌ماند.

> هش SHA-256 سمت مرورگر و رمز ثابت صرفاً برای نمونه اولیه‌اند و امنیت احراز هویت production را تأمین نمی‌کنند. نسخه نهایی باید احراز هویت را به Laravel منتقل کند.

## ساختار پوشه‌ها
```text
src/
  app/              تنظیمات، bootstrap و router
  components/       اجزای قابل استفاده مجدد
  data/             داده‌های نمایشی متمرکز
  db/               راه‌اندازی IndexedDB و عملیات عمومی
  pages/            صفحه‌ها و templateهای صفحه
  repositories/     دسترسی به موجودیت‌ها
  services/         منطق کاربردی و احراز هویت
  styles/           ورودی Tailwind و design tokens
```

## مدل داده محلی
| Object Store | کلید اصلی | کاربرد |
|---|---|---|
| users | id | حساب کاربری و hash رمز |
| profiles | userId | نام نمایشی و آواتار |
| sessions | id | نشست‌های ورود |
| accounts | id | حساب‌ها و کیف پول‌ها |
| transactions | id | تراکنش‌ها |
| categories | id | دسته‌بندی‌ها |
| budgets | id | بودجه‌ها |
| goals | id | اهداف مالی |
| settings | userId | تنظیمات کاربر |

ارتباط‌ها با شناسه‌هایی مانند `userId` و `accountId` نگهداری می‌شوند. در مهاجرت به MySQL، هر Object Store به جدول متناظر تبدیل و کلیدهای خارجی در migrationهای Laravel تعریف خواهند شد.

## صفحات موجود

- داشبورد
- تراکنش‌ها
- حساب‌ها
- گزارش‌ها
- بودجه‌بندی
- پروفایل و انتخاب آواتار
- دسته‌بندی‌ها، اهداف مالی و تنظیمات (صفحات پایه/placeholder)

## راهنمای اجرای مرحله‌ای
1. نصب Node.js و npm روی سیستم توسعه‌دهنده.
2. دریافت مخزن از GitHub.
3. اجرای `npm install` برای نصب وابستگی‌ها.
4. اجرای `npm run dev` و بررسی جریان خوش‌آمد، ثبت‌نام، ورود، بازگشت پس از refresh و خروج.
5. اجرای `npm run build` برای بررسی build نهایی.
6. توسعه صفحات با کامپوننت‌های مشترک و کلاس‌های Tailwind؛ افزودن CSS خام یا inline style مجاز نیست.
7. انتقال داده‌های نمایشی از fixture به Repositoryها و پیاده‌سازی عملیات CRUD محلی.
8. تعریف API adapter و جایگزینی منطق local auth با احراز هویت سمت سرور.
9. نوشتن migrationهای MySQL و APIهای Laravel متناظر با مدل داده.

## محدودیت‌های فعلی
- اطلاعات مالی داشبورد نمونه و نمایشی‌اند؛ CRUD مالی هنوز به IndexedDB متصل نشده است.
- ورود محلی امنیت production ندارد.
- صفحات دسته‌بندی‌ها، اهداف و تنظیمات placeholder هستند.
- service worker و سیاست cache آفلاین هنوز اضافه نشده‌اند.
