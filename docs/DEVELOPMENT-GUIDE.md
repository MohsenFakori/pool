# راهنمای توسعه و تحویل پروژه Pool

این سند روند ساخت نسخه پایه فرانت‌اند، تصمیم‌های معماری و روش اجرای آن را مرحله‌به‌مرحله ثبت می‌کند.

## فاز صفر — تعیین محدوده
- محصول: اپلیکیشن موبایلی مدیریت مالی شخصی.
- محدوده این نسخه: فرانت‌اند و داده‌های محلی مرورگر؛ بدون API و بک‌اند.
- صفحات: خوش‌آمدگویی، ورود، ثبت‌نام، داشبورد، تراکنش‌ها، حساب‌ها، گزارش‌ها، بودجه، پروفایل و چند صفحه پایه.
- قاب نمایش: عرض موبایلی ثابت؛ رابط برای نمایش دسکتاپ بازطراحی یا responsive نمی‌شود.
- مرجع بصری: UI Kit ارسالی «هزار ابزارک» و توکن‌های Candy.

## فاز یک — ابزارها و وابستگی‌ها
1. پروژه با npm مدیریت می‌شود؛ نصب Node.js و npm بر عهده توسعه‌دهنده است.
2. Vite سرور توسعه و build را فراهم می‌کند.
3. Tailwind CSS v4 از طریق افزونه رسمی Vite پردازش می‌شود.
4. فونت‌های Vazirmatn و Lalezar به‌صورت وابستگی npm نصب می‌شوند.
5. آیکن‌ها از Phosphor Icons Web استفاده می‌شوند.

فرمان‌ها:
```bash
npm install
npm run dev
npm run build
npm run preview
```

## فاز دو — تبدیل UI Kit به توکن‌های Tailwind
- رنگ اصلی، ثانویه، CTA، پس‌زمینه، سطح، متن، متن فرعی و خطوط از UI Kit به theme token تبدیل شدند.
- فونت متن و تیتر به ترتیب Vazirmatn و Lalezar هستند.
- شعاع کارت و سایه کارت به‌عنوان توکن تعریف شدند.
- فایل `src/styles/main.css` فقط شامل importها، directiveهای Tailwind و design tokenها است.
- هیچ selector، component CSS، inline style یا فایل CSS مستقل برای صفحه‌ها مجاز نیست.
- کلاس‌های Tailwind باید مستقیماً در templateها یا کامپوننت‌های JS استفاده شوند.

## فاز سه — سازمان‌دهی کد
- `app/config.js`: تنظیمات محصول، رمز پیش‌فرض نمایشی، نام دیتابیس، منوها و گزینه‌های آواتار.
- `app/router.js`: مسیریابی ساده مبتنی بر hash.
- `app/bootstrap.js`: راه‌اندازی برنامه، بررسی نشست و اتصال eventها.
- `app/utils.js`: ابزارهای عمومی مانند شناسه، فرمت مبلغ، escape و آیکن.
- `components/ui.js`: اجزای مشترک مانند دکمه، کارت، ورودی و عنوان صفحه.
- `components/shell.js`: قاب اپ، هدر، منوی همبرگری و منوی پایین.
- `pages/`: template صفحه‌ها و منطق ارائه اطلاعات صفحه.
- `services/`: منطق کاربردی مانند ثبت‌نام، ورود، نشست و پروفایل.
- `repositories/`: لایه دسترسی به هر موجودیت.
- `db/`: راه‌اندازی IndexedDB و عملیات عمومی.
- `data/demo-data.js`: fixtureهای نمایشی مستقل از templateها.

## فاز چهار — مدل ذخیره‌سازی مرورگر
IndexedDB شامل Object Storeهای زیر است:
- users
- profiles
- sessions
- accounts
- transactions
- categories
- budgets
- goals
- settings

هر رکورد شناسه مستقل دارد. روابط بین داده‌ها با شناسه‌های مرجع مانند `userId` و `accountId` ذخیره می‌شود. این الگو در MySQL به primary key و foreign key تبدیل می‌شود.

LocalStorage فقط برای دو داده سبک استفاده می‌شود:
- شناسه نشست جاری
- وضعیت دیده‌شدن صفحه خوش‌آمد

## فاز پنج — جریان اولین اجرا و احراز هویت نمایشی
1. اگر وضعیت خوش‌آمد در LocalStorage ثبت نشده و نشست معتبری وجود ندارد، صفحه خوش‌آمد نشان داده می‌شود.
2. با فشردن شروع، وضعیت خوش‌آمد ثبت می‌شود و صفحه ورود باز می‌شود.
3. اگر نام کاربری در دیتابیس وجود نداشته باشد، کاربر از لینک ثبت‌نام استفاده می‌کند.
4. ثبت‌نام فقط نام کاربری می‌گیرد؛ رمز از تنظیم مرکزی خوانده می‌شود.
5. رمز نمایشی با Web Crypto به SHA-256 تبدیل و در IndexedDB نگهداری می‌شود.
6. پس از ثبت‌نام، کاربر به‌صورت خودکار وارد می‌شود.
7. ورود موفق یک رکورد session در IndexedDB می‌سازد و شناسه آن را در LocalStorage قرار می‌دهد.
8. در بازدید بعدی، نشست خوانده می‌شود و داشبورد کاربر باز می‌شود.
9. خروج، نشست فعال را از IndexedDB و شناسه نشست را از LocalStorage پاک می‌کند؛ حساب و پروفایل حذف نمی‌شوند.

**هشدار امنیتی:** SHA-256 ساده و رمز ثابت برای محصول واقعی مناسب نیستند. در نسخه Laravel، رمز باید سمت سرور با الگوریتم استاندارد password hashing ذخیره شود و مدیریت session/cookie نیز سمت سرور انجام شود.

## فاز شش — ناوبری
- نوار پایین پنج مسیر دارد: خانه، تراکنش‌ها، حساب‌ها، گزارش‌ها و بودجه.
- منوی همبرگری مسیرهای تکمیلی مانند دسته‌بندی‌ها، اهداف و تنظیمات را نشان می‌دهد.
- نام و آواتار کاربر در هدر به پروفایل هدایت می‌شوند.
- منوها از تنظیمات مرکزی تولید می‌شوند؛ تعریف آیتم جدید در یک محل انجام می‌شود.

## فاز هفت — پروفایل
- نام نمایشی و آواتار در Object Store پروفایل ذخیره می‌شوند.
- فهرست آواتارها از config خوانده می‌شود.
- خروج فقط نشست جاری را حذف می‌کند.

## فاز هشت — داده‌های مالی و صفحات نمونه
- داده‌های نمایشی فعلی در یک فایل fixture قرار گرفته‌اند تا با template صفحه مخلوط نشوند.
- صفحات فعلی بیشتر برای نمایش معماری و مسیرهای ناوبری هستند.
- در مرحله بعد باید عملیات CRUD حساب، تراکنش، دسته‌بندی، بودجه و هدف در Repositoryها ایجاد شود.
- پس از ایجاد Repositoryهای واقعی، fixtureها فقط برای توسعه و تست باقی می‌مانند.

## فاز نه — آزمون دستی پس از نصب
1. پاک‌کردن داده‌های سایت در مرورگر یا استفاده از پروفایل مرورگر تازه.
2. بازکردن برنامه و اطمینان از نمایش خوش‌آمد.
3. انتخاب شروع و مشاهده صفحه ورود و رمز پیش‌فرض.
4. رفتن به ثبت‌نام و ایجاد یک نام کاربری جدید.
5. بررسی ورود خودکار و نمایش داشبورد.
6. refresh کردن صفحه و اطمینان از باقی‌ماندن نشست.
7. بازکردن پروفایل از نام یا آواتار.
8. تغییر نام نمایشی و آواتار و refresh برای بررسی ماندگاری.
9. خروج و اطمینان از بازگشت به صفحه ورود.
10. ورود دوباره با همان نام کاربری و رمز پیش‌فرض.
11. بازکردن منوی همبرگری و تک‌تک مسیرها و کنترل منوی پایین.
12. اجرای `npm run build` و رفع هر خطای build.

## فاز ده — مسیر مهاجرت به Laravel و MySQL
1. تثبیت مدل‌های دامنه و قواعد اعتبارسنجی.
2. ساخت migration برای users، profiles، sessions، accounts، transactions، categories، budgets، goals و settings.
3. تعریف foreign keyها و indexهای لازم.
4. پیاده‌سازی API و Form Requestهای Laravel.
5. انتقال منطق احراز هویت به Laravel و حذف رمز پیش‌فرض از کلاینت.
6. ساخت API adapter در فرانت‌اند و حفظ قرارداد Repositoryها تا حد امکان.
7. جایگزینی پیاده‌سازی IndexedDB با adapter مبتنی بر API؛ در صورت نیاز IndexedDB فقط برای cache آفلاین باقی بماند.
8. افزودن تست‌های واحد، integration و سناریوهای end-to-end.

## وضعیت تحویل فعلی
- اسکلت پروژه، پیکربندی npm/Vite/Tailwind، اجزای مشترک، مسیرهای نمونه، مدل IndexedDB و جریان احراز هویت محلی در مخزن قرار گرفته‌اند.
- داده‌های مالی صرفاً نمونه‌اند و CRUD مالی هنوز تکمیل نشده است.
- صفحات دسته‌بندی، اهداف و تنظیمات فعلاً placeholder هستند.
- اجرای واقعی `npm install` و `npm run build` باید روی سیستم توسعه‌دهنده انجام شود؛ این محیط به ترمینال محلی پروژه دسترسی ندارد.
